一、编译期四部曲 第 2 章

步骤命令输入 → 输出核心动作
1 预处理 gcc -E hello.c → hello.i 展开 #include 与 #define，处理条件编译 #ifdef，删除注释，添加行号标记
2 编译 gcc -S hello.i → hello.s 真正的"编译器"：词法→语法→语义→IR→优化→代码生成，产出汇编代码
3 汇编 gcc -c / as hello.s → hello.o 汇编指令逐条翻译成机器码，产出 ELF 可重定位目标文件（内含符号表与重定位表）
4 链接 ld *.o + 库 → a.out 节合并、符号解析、地址重定位，产出可执行文件
考点：gcc 只是调度入口，背后依次是四个独立工具 cpp → cc1 → as → ld。-E -S -c 正好是"走到哪一步就停"。产物后缀：.i（intermediate）、.s（assembly source）、.o（object）。

口诀：展、译、翻、链 —— 预处理"展"开、编译器"译"成汇编、汇编器"翻"成机器码、链接器把碎片"链"成整体。

二、编译器内部六步 第 2 章 —— 现代编译器的骨架

#阶段输入 → 输出做什么现代对照（LLVM）
1词法分析 Scanner字符流 → Token 流识别关键字、标识符、常量、运算符；发现非法字符Clang 前端
2语法分析 ParserToken → AST 语法树按语法规则推导（自顶向下/自底向上），发现语法错误
3语义分析 SemanticAST → 带标注的 AST类型检查、作用域检查、隐式转换
4中间代码生成AST → 三地址码 IR翻译成平台无关的中间表示LLVM IR / Relay IR
5优化 OptimizerIR → 更精简的 IR常量折叠、删除公共子表达式、死代码消除、循环优化Pass 管线 / MLIR dialect lowering
6目标代码生成IR → 汇编/机器码指令选择、寄存器分配，并附加重定位信息LLVM 后端
和你工作的关联：你在 mqbuilder.cpp 里做的 IR lowering，就是第 5 步的工程化形态——MLIR 的 dialect 逐层下降本质上就是"优化+翻译"合成的流水线。Relay IR → TVM TIR → 硬件码的链路，同样可以映射到 4→5→6 三步。

口诀：切、搭、查、生、优、成（词法切词、语法搭树、语义查错、生成三码、优化精简、产出指令）。

三、ELF 目标文件解剖 第 3 章

hello.o（类型 ET_REL）从上到下：

节 Section存什么备注
ELF HeaderMagic 7F 45 4C 46（即 0x7F ELF）、文件类型、机器架构、入口地址、段表位置readelf -h 查看
.text机器指令（函数体）只读、可执行
.rodata只读数据：字符串字面量、const 全局变量只读
.data已初始化的全局/静态变量占文件空间
.bss未初始化的全局/静态变量不占文件空间，只记录总大小
.symtab符号表：符号名 → 地址、大小、绑定属性（LOCAL/GLOBAL/WEAK）nm / readelf -s
.rel.text重定位表：.text 里哪些位置、按什么方式（R_X86_64_PC32 等）待链接时修正链接的关键线索
.strtab字符串表：符号名字符的仓库，.symtab 只存偏移省空间
高频考点 · 为什么 .bss 不占文件空间？
未初始化的全局/静态变量初值默认全 0；"全 0"没必要写进文件，只在节表里记录"多大"，装载时由操作系统一次性清零。
口诀：数据为 0 不写盘，只记大小待清零。（BSS 名字源自古老汇编伪指令 Block Started by Symbol）

符号修饰与函数签名（Name Mangling）

C++ 支持重载 → 把参数类型编进符号名：int add(int, int) 被修饰成 _Z3addii。这就是为什么：

  • C/C++ 混合编程要加 extern "C"——关闭名字修饰，让符号按 C 规则命名，双方才能互相找到；
  • 不同编译器的修饰规则不同 → C++ 二进制（ABI）兼容问题的根源。

四、静态链接 第 4 章 —— 两步走 + 符号仲裁

两步链接（Two-pass Linking）

步骤动作产出
① 空间与地址分配扫描所有输入 .o，统计各节长度属性，相似节合并（所有 .text 拼成大 .text、.data 拼成大 .data），确定合并后每节的虚拟地址全局符号表：每个符号有了最终虚拟地址
② 符号解析与重定位给"未定"符号找到主人（查全局符号表）；再按 .rel 重定位表，把 .text 里 call/jmp 等指令的地址修正成真实地址地址确定的可执行文件

强符号 vs 弱符号（三规则）

种类判定
强符号函数定义、已初始化的全局变量
弱符号未初始化的全局变量、__attribute__((weak)) 声明的符号

仲裁三规则：① 同名强符号出现两次 → 链接报错；② 强弱同名 → 强者胜、弱者让位；③ 弱弱同名 → 选占用空间最大的那个（未初始化变量先放 COMMON 块，链接期才能确定最终大小）。

口诀：强强报错、强弱取强、弱弱取大。

经典坑：两个 .c 里各写一行 int g; —— 编译不报错、链接也不报错（弱弱合并），但两个文件"共享"了同一个变量，查 bug 查到怀疑人生。-fno-common（新版 GCC 默认）已收紧此行为。

五、装载 第 6 章 —— 程序怎么进内存

进程虚拟地址空间（从低到高）

保留区（不可访问）→ .text → .data/.bss → 堆（向上生长）→ 共享库映射区 → 栈（向下生长）→ 命令行参数与环境变量

页映射装载

  • 现代装载以页（通常 4KB）为单位；OS 先只在页表里"登记"映射，真正访问到某页才把它调入物理内存（惰性装载、缺页中断）；
  • 装载视角下不看 Section 而看 Segment：Program Header（readelf -l）里的 PT_LOAD 项，把权限相同的相邻节合并成一个段整段映射——只读执行段、只读数据段、可读写段；
  • 程序真正入口是 ELF Header 的 e_entry（通常是 _start），经 __libc_start_main 做完初始化后才调用 main——所以"main 是程序入口"是善意的谎言。

口诀：节给链接器看，段给 OS 装。

六、动态链接 第 7 章 —— GOT / PLT / 延迟绑定

为什么要动态链接

  • 省内存：静态链接时每个程序都带一份 libc，100 个进程就 100 份；共享库只映射一份物理内存，全进程共享；
  • 好升级：库修个 bug，替换 .so 即可，所有程序立即受益，不用逐个重新编译链接；
  • 代价：启动时要做动态符号解析与重定位（有性能开销），并有版本兼容（ABI）问题。

运行机制

  • OS 创建进程后发现 .interp 节（PT_INTERP）记录的动态链接器 /lib/ld-linux.so，先把控制权交给它：装载所有依赖 .so → 完成符号解析与重定位 → 再跳回程序入口；
  • 地址无关代码 PIC（-fPIC）：代码段不含绝对地址——模块内调用用相对跳转、模块内数据用 PC 相对寻址、模块间数据/函数经 GOT 间接访问，这样同一份代码可以映射进任意进程不同地址；
  • GOT（Global Offset Table，数据段）：地址簿，每项存一个外部符号的真实地址；
  • PLT（Procedure Linkage Table，代码段）：跳板，函数调用先跳 PLT 再查 GOT；
  • 延迟绑定：函数第一次被调用时才请动态链接器解析地址并回填 GOT——启动时不必解析全部符号，只解析用到的；
  • 显式运行时链接：dlopen / dlsym / dlclose —— 插件系统的基石。

口诀：GOT 记地址，PLT 当跳板，首调才查号（延迟绑定）。

九、自测十题 合上笔记再答，答不出的回翻对应节

1. gcc -E / -S / -c 分别停在哪一步、产物是什么？
答：-E 停在预处理后（.i）；-S 停在编译后（.s 汇编文件）；-c 停在汇编后（.o 目标文件）。
2. .bss 和 .data 的区别？为什么 .bss 不占文件空间？
答：.data 存已初始化全局/静态变量，占文件空间；.bss 存未初始化的。未初始化变量默认全 0，全 0 没必要写进文件，只记录总大小，装载时由 OS 清零。
3. 编译器内部六个阶段的顺序与各阶段输入输出？
答：词法（字符→Token）→ 语法（Token→AST）→ 语义（类型/作用域检查）→ 中间代码（AST→三地址码）→ 优化（IR→IR）→ 目标代码生成（IR→机器码 + 重定位信息）。
4. 强符号、弱符号怎么判定？三条仲裁规则是什么？
答：强 = 函数定义、已初始化全局变量；弱 = 未初始化全局变量、weak 属性。规则：强强报错、强弱取强、弱弱取大（COMMON 块，链接期定大小）。
5. 静态链接"两步"指什么？
答：① 空间与地址分配：相似节合并、确定虚拟地址、建立全局符号表；② 符号解析与重定位：给未定符号找主人，按 .rel 表修正 call/jmp 地址。
6. Section 和 Segment 的区别？分别用什么命令查看？
答：节是链接视角（readelf -S），段是装载视角（readelf -l）；权限相同的相邻节合并成 PT_LOAD 段。节给链接器看，段给 OS 装。
7. 为什么需要动态链接？说两点核心动机。
答：① 省内存：多个进程共享同一份共享库代码；② 好升级：更新 .so 不需要重新编译链接所有依赖它的程序。
8. GOT 和 PLT 分别是什么、放在哪个段？延迟绑定是什么？
答：GOT 是全局偏移表（数据段），存符号真实地址；PLT 是过程链接表（代码段），是函数调用跳板。延迟绑定：函数第一次被调用时才解析地址回填 GOT，加快启动。
9. extern "C" 的作用是什么？为什么需要它？
答：关闭 C++ 的名字修饰（name mangling），让符号按 C 风格命名（如纯函数名）。因为 C++ 为支持重载把参数类型编进符号名（_Z3addii），C 代码按原名查找就找不到，混合编程会链接失败。
10. 从低地址到高地址写出进程虚拟地址空间的布局。
答：保留区 → .text（只读代码）→ .data/.bss → 堆（向上生长）→ 共享库映射区 → 栈（向下生长）→ argv/environ。
